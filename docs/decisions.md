# Decision log

Short record of decisions and why. Newest at the bottom. Proposals that are not
decided yet live in [design.md](design.md), marked **Proposal**.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-25 | The game is original, made "in the spirit of" early-2000s online RPGs. No names, lore, data, art or music from existing games, nothing from their clients or fan databases. Assets are our own or CC0 / similarly clean-licensed. | Legal safety and a game that can stand on its own. |
| 2026-11-25 | Turn-based, no 3D. MVP UI is cards, icons and text; a 2D engine may come later. | Small scope for a hobby project; works well on phones. |
| 2026-11-25 | Targets: browser first, mobile through a PWA, app stores later through Capacitor. | One codebase for all platforms. |
| 2026-11-25 | Stack: TypeScript everywhere, pnpm monorepo (`client`, `server`, `shared`), Node server with authoritative game logic, Postgres. | One language, shared rules between client and server, cheat-resistant. |
| 2026-11-25 | Server and accounts from the start, no offline-only version. | The living-world feel and later PvP need a server anyway. |
| 2026-11-25 | Game language is English. | Wider audience; one language to maintain. |
| 2026-11-25 | MVP scope: levels 1–20, profession change at 20, five races, two archetypes (warrior, mage), one village and three hunting zones on a node map, 1v1 PvE with a zone boss, two gear grades, charges, ~15 crafting recipes, 8–10 quests, shop/warehouse/blacksmith. | Smallest game that still has the full loop: hunt, loot, craft, gear up, change profession. |
| 2026-11-25 | Async arena PvP is step two, after the MVP. Deferred: real-time PvP, clans and sieges, trading, enchanting, parties, pets, 2D engine. | Keep the MVP finishable. |
| 2026-11-25 | Title: **Lost to Nostalgia**, short name **L2N**. | Chosen by Aleh; matches the repo name. |
| 2026-11-25 | Docs live in the repo (README, design doc, this log, MVP plan) and are updated in the same pull requests as code. | Docs that drift from code are worse than none. |
| 2026-11-25 | Combat engine is pure and seeded; numbers come from formulas in the design doc, checked by a balance simulation test. | Reproducible fights, server-side validation, balance changes are reviewable. |
| 2026-11-25 | Accounts use email + password. Passwords are hashed with Node's built-in scrypt; sessions are random tokens in an HttpOnly, SameSite=Lax cookie, stored in Postgres only as a SHA-256 hash, valid 30 days. | No native dependencies and no third-party auth service; a leaked database does not leak live sessions; easy to revoke. |
| 2026-11-25 | Character names: 3–16 letters A–Z, stored capitalised ("Aldric"), unique regardless of case. Up to 4 characters per account. | Readable names in chat and the chronicle, no look-alike impersonation. The slot count can grow later. |
| 2026-11-25 | Persistence goes through a `Store` interface with a Postgres and an in-memory implementation that pass the same contract tests. Without `DATABASE_URL` the dev server uses the in-memory store; in production it refuses to start. | Fast tests and a zero-setup dev loop without letting the two drift apart. |
| 2026-11-25 | Death penalty: lose 4% of the current level's XP bar (never a level), respawn in Brackwell Square with 30% HP and Mana. Auto-battle allowed against mobs 4+ levels below. | Chosen by Aleh for stage 2: dying should hurt, farming weak mobs should be quick. |
| 2026-11-25 | Every game action on a character runs in one database transaction holding the character's row lock; at most one fight in progress per character (unique partial index). The fight's RNG state stays on the server. | No double-resolved rounds or races between moving, resting and fighting; the client cannot predict rolls. |
| 2026-11-25 | Until equipment exists, characters fight with a provisional kit equal to Ironbound/Steelsworn gear of their level. | Keeps stage 2 fights at the balance targets without inventing an item system early. |
| 2026-11-25 | The repository is public under the MIT licence (`LICENSE`, copyright Aleh). It covers everything in the repo, code and game content alike. A separate content licence (e.g. CC BY-SA for lore, texts and data) may be added later. | Chosen by Aleh; simple and permissive for a hobby project. |
| 2026-11-25 | Test coverage is measured with Vitest's built-in V8 provider across all packages and reported in GitHub Actions (job summary plus HTML artifact). No external coverage service and no enforced threshold for now. | Aleh asked for coverage; the repo is public, so Actions is free and needs no sign-up. A threshold can be added once Aleh picks one. |
| 2026-11-25 | Items are rows owned by a character (one per piece of equipment, one per stack of anything else) in one of three places: bag, worn, warehouse. Item stats are never stored; they come from the template, item level and rarity through the grade formulas. | Balance changes apply to items already owned; one table covers inventory, gear and storage. |
| 2026-11-25 | Charges and draughts are taken out of the bag when a fight starts and the rest handed back when it ends; loot rolls continue the fight's hidden RNG. The warehouse is per character for now. | No inventory bookkeeping inside fight rounds, nothing for the client to predict, and per-character locking stays enough. An account-wide warehouse can come later. |
| 2026-11-25 | Dropped equipment is always for the killer's archetype. | With no trading yet, gear for the other archetype would only be vendor junk. |
| 2026-11-25 | Keep item rarity: Common, Uncommon (×1.08), Rare (×1.16 plus +2% crit or +3% max HP), rolled on drops and crafts. | Chosen by Aleh for stage 3: exciting drops are the heart of the genre's loot loop. |
| 2026-11-25 | Ember vials boost a mage's damaging spells (×1.3, one vial per cast); warriors' whetstones keep boosting basic attacks. The grade II ember vial costs 4 silver. | Chosen by Aleh for stage 4: vials were nearly useless for mages, who rarely make basic attacks. Mages use about 3 charges per fight to a warrior's 2, so the cheaper grade II vial keeps their kills paying for their charges. |
| 2026-11-25 | Recipes are items; using one learns it into the character's recipe book (stored on the character). The smith sells the first ten; Steelsworn gear recipes drop from elites and the boss, for the killer's archetype only. Set recipes make all five armour pieces at once. | Recipes can drop like any loot, the book costs no bag space, and one set recipe per grade keeps the list at 15. |
| 2026-11-25 | The Ashen Warden is fought by challenging it in the Warden's Crypt, never met while hunting, with no respawn timer in the MVP. The boss role is ×5 HP, ×1.4 attack, ×1.3 defence (was ×6, ×1.5, ×1.4). | A boss fight should be a choice you prepare for. With the old numbers even a prepared level 20 mage lost more often than not, and the level cap leaves no margin to outlevel it. |
| 2026-11-25 | Quests are taken and turned in at the Brackwell notice board; the quest log is a jsonb column on the character. Quest items drop only while a quest needs them, from the fight's own RNG. Quest XP is about a third of the XP to level 20. | One place to find quests keeps the MVP small; the log is tiny and always read with the character; drops stay unpredictable to the client. |
| 2026-11-25 | The Burrow Queen (level 7 elite) is a quest foe: challenged in the Burrows only while her quest is active, not in the hunting pool. | As a hunting-pool elite she killed level 5 mages six times an hour in the economy simulation. |
| 2026-11-25 | Bandit Toll asks for the Brigand Captain and 5 Toll Brigands instead of "three bandit elites": Thornwood has only one bandit elite. | Killing one elite three times at one encounter in ten would be a slog. |
| 2026-11-25 | Professions (chosen once, at level 20, by turning in Warden's Crypt): a passive plus two skills each. Vanguard and Hexbinder get sustain (drains, a curse that weakens the enemy), Reaver and Stormcaller burst. | Two skills keep the level 20 cap meaningful without a balance pass on eight; more can come with levels above 20. Every profession beats the Warden more often than the plain archetype. |
| 2026-11-25 | Living world as proposed in the design doc: global and zone chat, player counts on nodes, a chronicle feed and fallen markers. | Confirmed by Aleh by starting stage 6. |
| 2026-11-25 | The client polls one endpoint every 4 s for counts, new chat lines, the chronicle and markers; no websockets yet. Presence is a `seen_at` time on the character, refreshed by that poll. | Works through any proxy and with several server processes on one Postgres; a few seconds of lag is fine for a turn-based game. |
| 2026-11-25 | Chat safety: 200 characters, control and invisible characters removed, always rendered as text; 1 line per 2 s and 8 per minute per account (counted in Postgres); global chat from level 2; client-side `/ignore`; an operator mute by character name that also deletes the account's lines. | Basic protection for user-generated text in a public game without building moderation tools yet. The level gate costs a new player a few minutes and keeps throwaway spam accounts out of the channel everyone reads. |
| 2026-11-25 | The chronicle records boss kills, profession changes and Rare crafts, and marks the first time anyone does each. Fallen markers last 30 minutes. | The deeds named in the design doc; "first ever" gives early players something to race for. |
| 2026-11-25 | The PWA caches only the page and its built files (service worker in `public/sw.js`); the API is never cached. | The server is the source of truth; offline the game opens and says it is offline instead of showing stale state. |
| 2026-11-25 | The first icon set waits for art generated with Venice; letter placeholders stay until then. | Chosen by Aleh for stage 6. |
